# Project Skill & Team Allocation Analysis

**Baseline phase:** Not stage-specific — see [8-stage baseline overview](../../../code/baseline-phases.md) for the full sequence.

I want you to analyze this project's **actual baseline codebase and technical stack** and help us decide what our 5-person student tech team should learn and work on during this trimester.

Do not redesign the project.

Do not propose adding technologies simply because they are popular.

Do not assume that students need to implement the entire project from scratch.

The baseline already has much of the infrastructure, integrations, project structure, and technical connections established. The purpose of the remaining work is to develop meaningful features and systems on top of that foundation.

Our goal is:

> **Use AI to accelerate tedious implementation and infrastructure work, while keeping the technically meaningful systems and engineering decisions understandable and owned by students.**

---

---

# 2. Classify the skills by value

For every skill, classify it into one of these categories:

### A — High-value / strong resume skill

Skills that are broadly useful in industry and can produce meaningful technical experience.

### B — Good supporting skill

Useful and employable, but probably should not consume the majority of someone's trimester.

### C — Niche / specialist skill

Technically interesting or differentiating, but applicable to fewer jobs.

Clearly state the niche.

For example:

> Browser-based 3D interaction — niche compared with general web development, but highly relevant to graphics, simulation, XR, digital twin and interactive applications.

### D — Low-value / mostly implementation work

Work that is necessary for the project but provides relatively little learning or resume differentiation.

### E — Tedious / AI-suitable

Work that can reasonably be accelerated or largely generated by AI because it is repetitive, boilerplate, mechanical, or low in learning value.

---

# 3. Distinguish "technology" from "actual skill"

Do not treat simply using a technology as evidence of expertise.

For example:

> "Used PostgreSQL"

is weak.

Whereas:

> "Designed and integrated persistent project data using PostgreSQL"

is a meaningful engineering capability.

Therefore, for important technologies explain:

**Technology → actual engineering skill gained**

Examples:

```text
Three.js
→ browser-based 3D rendering and scene manipulation

FastAPI
→ API/backend service development

PostgreSQL
→ relational data modelling and persistence

TypeScript
→ application architecture and typed software development

Cloud deployment
→ deploying and operating a production-like application
```

Base these descriptions on what the project actually allows students to do.

---

# 4. Identify what AI should do

Look at the actual project work and identify tasks that are:

* repetitive
* boilerplate
* mechanical
* low learning value
* easy to verify
* unlikely to be useful interview discussion points

These are good candidates for AI assistance.

Examples might include:

* repetitive UI components
* boilerplate API wiring
* DTO/type generation
* test scaffolding
* simple CRUD
* configuration
* documentation
* repetitive adapters
* mock data
* straightforward glue code

But verify against the actual project.

---

# 5. Identify what students should understand themselves

Identify the parts where **AI should not completely do the work** because understanding them would provide substantial engineering value.

Examples might include:

* core architecture
* rendering systems
* transform/gizmo mathematics
* interaction engine
* serialization model
* state management
* database design
* API design
* authentication/security boundaries
* performance investigation
* testing strategy
* important debugging

The distinction should be:

> **AI can help write the code. Students should understand the system and own the important technical decisions.**

We do NOT need to hand-write every line of the project.

---

# 6. Consider the Singapore job market

Use current Singapore software engineering job-market information to determine which of the project's skills are broadly useful to employers.

Do not rank every technology simply by popularity.

Consider:

* demand
* transferability between jobs
* graduate relevance
* usefulness in software engineering roles
* usefulness in games/graphics/3D roles
* usefulness in cloud/backend roles
* portfolio value

Clearly distinguish:

**Broad industry skill**

from

**specialist/niche skill**

and

**project-specific knowledge.**

---

# 7. Profile our five-person team

Use the following information only as a starting point.

### Person 1 — Rendering / Generalist

Interested in:

* rendering
* graphics
* generalist programming

Identify which project skills would give this person the strongest technical growth.

---

### Person 2 — Games / Full-stack

Interested in:

* entering the games industry
* becoming more full-stack

Identify a combination of skills that gives this person useful game/interactive experience while also developing transferable software engineering skills.

---

### Person 3 — Modelling / Art / Design

Interested in:

* modelling
* art
* design

Identify technical skills that can bridge their interests with the technology side of the project.

Do not force them into purely backend/software engineering work if there is a meaningful technical-art / 3D / tooling capability available.

---

### Person 4 — Less involved / prefers following rather than deciding

This person is more laid-back and less inclined to make architectural decisions.

Do not automatically give them the least valuable work.

Instead identify a clearly scoped technical responsibility where:

* requirements are concrete
* success can be tested
* the work has a clear boundary
* they can build genuine competence
* they do not need to make many high-level architecture decisions

---

### Person 5 — Team lead / general software engineering

Treat this person as the person who needs to understand the overall architecture and integration.

Identify what technical area would complement the other four rather than duplicating them.

Do not assume the team lead should personally implement everything.

# FINAL QUESTION

Answer this directly:

> **If we have 5 students, one trimester, an already-integrated baseline, and access to AI, what technical skills should each person deliberately develop through this project so that we gain meaningful engineering experience without wasting time manually implementing low-value work?**

The goal is **not** to make every student build everything.

The goal is:

> **A manageable project where each student develops one meaningful technical capability, contributes to a real integrated system, and finishes with something credible to discuss on their resume and in an interview.**
